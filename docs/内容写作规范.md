# 内容写作规范

统一写作格式的目的：让所有人写出来的文章排版一致、可被 CI 自动检查、日后易于维护。

## 一、新建文章

```bash
# 推荐方式，会自动套用 archetype 模板
hugo new post/my-article.md --kind post
```

文件名用**英文小写加连字符**，不要用中文或空格：

| 文件名 | 评价 |
| --- | --- |
| `hugo-build-optimization.md` | ✅ 推荐 |
| `Hugo构建优化.md` | ❌ 中文名，URL 编码后难读 |
| `my article.md` | ❌ 含空格，需转义 |

文件名决定 URL，发布后再改会导致原链接失效。

## 二、front matter 字段

文章头部必须包含以下字段：

```toml
+++
title = '文章标题'
date = '2026-10-16T08:40:00+08:00'
lastmod = '2026-10-16T08:40:00+08:00'
draft = true
description = '一句话摘要，用于列表页和搜索引擎'
categories = ['技术']
tags = ['Hugo', 'CI/CD']
+++
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 文章标题，会显示在页面和列表 |
| `date` | ✅ | 创建时间，决定排序。archetype 会自动填 |
| `lastmod` | 建议 | 最后修改时间，更新文章时同步改 |
| `draft` | ✅ | `true` 不发布。定稿后必须改为 `false` |
| `description` | 建议 | 列表页摘要。留空则截取正文开头 |
| `categories` | 建议 | 分类，建议**单层、数量少** |
| `tags` | 建议 | 标签，可多个、可自由发挥 |
| `banner` | 可选 | 文章页头图 URL |
| `cover` | 可选 | 列表卡片封面 URL。留空则从 `data/covers.yml` 随机取 |

`categories` 和 `tags` 的区别：分类是**抽屉**（少而稳定），标签是**索引**（多而灵活）。
一篇讲 Hugo 部署的文章，分类是 `技术`，标签是 `Hugo`、`CI/CD`、`GitHub Pages`。

## 三、正文格式

### 标题层级

从 `##` 开始，不要用 `#`（文章标题已由 front matter 提供），也不要跳级：

```markdown
✅ 正确
## 一级小节
### 二级小节

❌ 错误：跳级
## 一级小节
#### 直接跳到四级
```

### 代码块

必须标注语言，否则没有语法高亮：

````markdown
✅ 正确
```bash
hugo server
```

```yaml
theme: reimu
```

❌ 错误：不标语言
```
hugo server
```
````

### 图片

图片统一放 `static/images/`，正文用绝对路径引用：

```markdown
![构建流程示意图](/images/build-flow.webp)
```

- 图片格式优先 `webp`（体积比 png/jpg 小很多），其次 `png`
- 必须写 alt 文本（方括号里的内容），既为无障碍也为图片加载失败时的兜底
- 大图先压缩再提交，单张控制在 500KB 以内

### 链接

用有意义的锚文本，不要写「点击这里」：

```markdown
✅ 正确
参见 [Hugo 官方文档](https://gohugo.io/documentation/)

❌ 错误
参见 [点击这里](https://gohugo.io/documentation/)
```

站内链接用**绝对路径**，与 `baseURL` 配合：

```markdown
[关于我](/about/)
[上一篇文章](/post/hello-world/)
```

### 中英文混排

中英文之间加空格，中文标点用全角：

```markdown
✅ 正确
使用 Hugo 构建站点，速度很快。

❌ 错误
使用Hugo构建站点,速度很快.
```

### 列表与表格

- 有序列表用于**步骤**，无序列表用于**并列项**
- 超过 3 列的对比信息用**表格**而非列表
- 表格前后留空行，否则不会渲染

## 四、自动检查

CI 会在推送时对 `content/**/*.md`、`README.md`、`CONTRIBUTING.md` 执行 markdownlint 检查，
规则配置在 `.markdownlint.json`。

本地想提前自查，用 Docker 跑一次：

```bash
docker run --rm -v "$PWD:/workdir" davidanson/markdownlint-cli2:latest "content/**/*.md" "README.md" "CONTRIBUTING.md"
```

或装 Node 后直接用 npx：

```bash
npx markdownlint-cli2 "content/**/*.md" "README.md" "CONTRIBUTING.md"
```

已按中文写作习惯放宽的规则：

| 规则 | 处理 | 原因 |
| --- | --- | --- |
| 行长度限制 | 关闭 | 中文按字符计长，硬性换行反而破坏段落 |
| 内联 HTML | 允许 | Hugo 短代码排版需要 |
| 首行必须 H1 | 关闭 | 标题来自 front matter |
| 裸 URL | 允许 | 文档中常直接贴链接 |

## 五、发布前自查

- [ ] `draft` 已改为 `false`
- [ ] 文件名是英文小写加连字符
- [ ] `categories` 和 `tags` 已填
- [ ] 代码块都标了语言
- [ ] 图片 alt 文本已写，文件已压缩
- [ ] 本地 `hugo server` 预览排版正常
