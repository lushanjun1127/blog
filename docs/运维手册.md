# 运维手册

记录 CI/CD 机制、常见故障的排查方法和主题升级流程。
**全是实际踩过的坑**，遇到问题先查这里。

## 一、发布机制

推送 `main` 分支即自动发布。

```text
push 到 main
      │
      ▼
┌──────────────┐
│  Quality     │  Markdown 规范检查 + 试构建
│  gate        │  不通过 → 流程终止，不部署
└──────┬───────┘
       │ 通过
       ▼
┌──────────────┐
│  Build       │  安装 Hugo extended，构建站点
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Deploy      │  发布到 GitHub Pages
└──────────────┘
```

耗时通常 1 分钟左右。状态在 <https://github.com/lushanjun1127/blog/actions> 查看。

流水线定义在 `.github/workflows/hugo.yml`。

## 二、故障排查

### 问题：构建报 `TOCSS: failed to transform "xxx.scss"`

**原因**：Hugo 装的是标准版，Reimu 主题用 SCSS，需要 extended 版。

**排查**：

```bash
hugo version
# 若输出中没有 +extended，就是这个问题
```

**解决**：

```bash
# Windows
winget install --id Hugo.Hugo.Extended --accept-source-agreements --accept-package-agreements

# macOS
brew install hugo

# 手动下载
# https://github.com/gohugoio/hugo/releases
```

> **注意**：WinGet 里的 `Hugo.Hugo` 是标准版，`Hugo.Hugo.Extended` 才是扩展版。装错包是常见失误。

---

### 问题：主题样式不生效，页面裸奔（无 CSS）

**原因**：git submodule 没拉取，`themes/reimu/` 是空目录。

**排查**：

```bash
ls themes/reimu/
# 空的就是没拉取
```

**解决**：

```bash
git submodule update --init --recursive
```

克隆时带上参数可避免此问题：

```bash
git clone --recurse-submodules https://github.com/lushanjun1127/blog.git
```

---

### 问题：CI 在 `Quality gate` 环节失败

**原因**：Markdown 不符合规范，或站点构建报错。

**解决**：

1. 点开失败的 job，看是 `Markdown lint` 还是 `Verify site builds` 报错
2. 若是 lint：本地跑一次定位问题

   ```bash
   npx markdownlint-cli2 "content/**/*.md" "README.md" "CONTRIBUTING.md"
   ```

3. 若是构建：本地跑 `hugo --minify` 复现，按报错修
4. 若确认某条 lint 规则不适合本项目，改 `.markdownlint.json` 放宽，而**不是**绕过检查

---

### 问题：本地正常，线上 404

**原因**：`baseURL` 与线上的子路径不一致。

线上地址是 `https://lushanjun1127.github.io/blog/`（**带 `/blog/` 子路径**），
本地预览用的是根路径 `http://localhost:1313/`。站内链接若写死绝对路径容易出问题。

**解决**：

- 站内链接用 `/posts/xxx/` 这种以 `/` 开头、相对 `baseURL` 的写法 —— Hugo 会自动补全
- 不要写死 `https://lushanjun1127.github.io/blog/...` 开头的完整 URL
- CI 里 `--baseURL "${{ steps.pages.outputs.base_url }}/"` 会自动注入正确地址，
  `hugo.toml` 里的 `baseURL` 会被覆盖，所以不用手动维护

---

### 问题：推送后线上没变化

**排查顺序**：

1. 看 [Actions](https://github.com/lushanjun1127/blog/actions) 最新一次运行是否成功
2. 若失败，按上面的方法定位
3. 若成功，可能是浏览器缓存，强制刷新（`Ctrl+Shift+R`）
4. GitHub Pages 偶有延迟，等 1-2 分钟

---

### 问题：`content/post/_index.md` 被误删

**现象**：`/post/` 路径生成了一个空列表页。

**原因**：这个文件用于**阻止**生成 `post/index.html`，且必须保持 `draft: true`。删掉就会生成。

**解决**：从 git 恢复：

```bash
git checkout HEAD -- content/post/_index.md
```

同理，`content/archives/_index.md` 也不可删除，它承载归档页。

---

### 问题：`covers.yml` 报警告

```text
WARN  The []interface {} data from 'covers.yml' overridden by higher precedence
```

**原因**：项目根和主题内都有 `covers.yml`，Hugo 提示项目根的覆盖了主题的。这是**正常行为**，
说明覆盖生效了。若要消除警告，让文件内容非空即可。

---

### 问题：`libsass was deprecated` 警告

```text
WARN  css.Sass: libsass was deprecated in Hugo v0.153.0
```

**原因**：Reimu 主题内部用的旧版 Sass transpiler。属**主题上游问题**，不是配置错误。

**处理**：忽略，不影响构建与显示。等主题升级修复。若以后升级 Hugo 到移除 libsass 的版本
导致构建失败，则需要给主题提 issue 或改用 Dart Sass。

---

### 问题：CI 报 Node.js 20 deprecated

```text
Node.js 20 is deprecated. The following actions target Node.js 20...
```

**原因**：官方 action（`actions/checkout@v4`、`actions/configure-pages@v5` 等）内置的运行时版本。
**不是你的配置问题**。

**处理**：忽略。等这些 action 发布新版本后把版本号加一即可（例如 `checkout@v5`）。

## 三、本地环境重建

换电脑或环境损坏时，从零恢复：

```bash
# 1. 安装 extended 版 Hugo（见上文问题一）
hugo version   # 确认有 +extended

# 2. 克隆仓库（含子模块）
git clone --recurse-submodules https://github.com/lushanjun1127/blog.git
cd blog

# 3. 启动预览
hugo server --bind 127.0.0.1 --port 1313 --baseURL http://localhost:1313/
```

无需 `npm install`，本项目没有 Node 依赖（CI 里的 Node 步骤是为兼容主题可能的
前端构建而保留的，当前不会执行）。

## 四、主题升级

主题是 git submodule，升级就是切到新版本并提交指针变更。

```bash
cd themes/reimu

# 查看当前版本
git describe --tags

# 拉取最新
git fetch --tags

# 查看可用版本
git tag -l | tail -20

# 切到目标版本（示例）
git checkout v0.17.0

cd ../..

# 本地验证，确认没坏
hugo --minify
hugo server --bind 127.0.0.1 --port 1313 --baseURL http://localhost:1313/
```

本地预览确认无误后再提交：

```bash
git add themes/reimu
git commit -m "chore: 升级 Reimu 主题至 v0.17.0"
git push origin main
```

**升级前必须本地验证。** 主题大版本可能改了配置字段名，直接推可能导致线上构建失败。

想回退：

```bash
cd themes/reimu && git checkout v0.16.1 && cd ../..
git add themes/reimu
git commit -m "chore: 回退 Reimu 主题至 v0.16.1"
```

> 当前锁定版本：**v0.16.1**

```yaml
env:
  HUGO_VERSION: 0.168.0
```

## 六、紧急回滚

线上出问题需要立刻恢复时：

```bash
# 方式一：撤销最近一次提交
git revert HEAD
git push origin main

# 方式二：撤销指定提交
git log --oneline -10      # 找到目标提交
git revert <commit-hash>
git push origin main
```

优先用 `revert` 而非 `reset --hard` —— 前者保留历史，可追溯，也不会影响协作者的本地仓库。
